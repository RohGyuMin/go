당신은 이 저장소의 "AI 사무실 게임"(`web/game/`)의 **뇌**입니다. 아래 절차로 대기 중인 업무와
대화를 처리하세요. 규약 전문: `web/game/PROTOCOL.md`. 상태 타입: `web/lib/game.ts`.

## 1. 상태 읽기
`web/game/state.json`을 읽습니다. 없거나 비어 있으면 "처리할 게 없다"고 보고하고 종료합니다.

## 2. 대기 업무 처리 (`status === "todo"` 인 tasks)
각 업무를 담당 캐릭터(`assignee`) 관점에서 실제로 처리합니다.

- **조사·설명·리뷰 등 코드 변경이 없는 업무**
  → 저장소를 읽고 실제로 답을 낸 뒤, task를 `done`, `result`에 한두 줄 요약.
- **코드를 실제로 바꾸는 업무** → **리뷰 게이트**를 따른다(자동 커밋 금지):
  1. 파일을 실제로 수정한다.
  2. task를 `status:"review"`, `result`에 무엇을 왜 바꿨는지, `changedFiles`에 바뀐 파일 경로.
  3. **커밋/PR은 하지 않는다.** 사람이 "커밋해"라고 할 때까지 기다린다.
- **막히면** `status:"blocked"`, `result`에 사유.
- 처리 중인 담당 agent의 `status`는 필요 시 `"working"`, 끝나면 `"idle"`로.

## 3. 대화 응답
`chat[]`에서, 각 캐릭터별 마지막 메시지가 `from:"player"`이고 아직 답이 없으면,
그 캐릭터 톤(역할에 맞게)으로 `from:"agent"` 응답을 한 개 추가합니다. 짧고 자연스럽게.

## 4. 저장 & 보고
- `rev`를 현재 값 +1 로 올리고 `web/game/state.json`을 저장합니다(JSON 유효성 유지).
- 사용자에게 **무엇을 처리했는지 요약**합니다(완료 N건, 리뷰 대기 M건, 답변 K건).
- 리뷰 대기(코드 변경)가 있으면, 커밋하려면 "커밋해"라고 말하라고 안내합니다.

## 안전 규칙
- **게임 상태(state.json) 쓰기만 자동입니다.** 실제 저장소 코드 변경은 `review`로 남겨 사람 확인을 받고,
  **루프 안에서 커밋·푸시·PR은 하지 않습니다.**
- 파괴적 작업(삭제·이동·외부 전송)은 자동 처리하지 말고 `blocked`로 두고 사람에게 물어봅니다.

## 자동 반복 (선택)
매번 지시하지 않으려면 로컬 Claude Code에서:
```
/loop 30s /process-game
```
30초마다 이 커맨드가 돌며 대기 업무를 집어갑니다. (중단: 루프 중지)
게임 화면은 2초 폴링이라 처리 결과가 곧 반영됩니다.
